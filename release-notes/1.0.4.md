# mdreader 1.0.4

一次集中的界面与交互缺陷修复：窗口圆角、边框连贯性、侧栏状态记忆、侧栏最小宽度、大纲栏横向滚动条、窗口大小/位置记忆，以及拖入文件替换空白标签、CRLF 文件假脏导致误弹保存提示、拖动窗口后边框被系统边框盖住。

## 窗口四角外多出一圈直角

**现象**：窗口是 8px 圆角，但圆角外面还套着四个直角，看起来像"圆角边框压在底下的直角上面"。

**原因**：1.0.1 为了修四边边框用了 `thickFrame: false`，窗口因此失去 `WS_THICKFRAME`（可调整大小的边框样式）。Windows 11 的 DWM 只对带 thick frame 的窗口自动裁圆角，所以这个窗口在系统层面是**直角**；页面里那圈 8px 圆角边框只是画在方形轮廓内部，弧线以外露出的必然是窗口底色（深色主题下是 `#100e17` 的方角）。

**修复**：建窗后调用 `DwmSetWindowAttribute(hwnd, DWMWA_WINDOW_CORNER_PREFERENCE, DWMWCP_ROUND)`，让 DWM 自己按 8px 把窗口裁成圆角，与页面边框半径一致。Windows 10（build < 22000）或调用失败时自动跳过，只降级、不影响其它功能。

- 实现：`mdreader-electron/src/util/windowStyleUtil.js` 新增 `applyNativeRoundedCorners`，`mdreader-electron/src/util/document-session/windowLifecycleService.js` 建窗时调用。

## 四边青色边框"有的有、有的没有"

逐像素抓渲染层看了：上、下、左、右四条边**都在**，都是 1.33px 的青色线（`rgba(14,210,247,0.5)`）。看起来"缺边"是三个原因叠加：

- 1.33px 半透明线在深色底上对比太弱，正对着看几乎看不见；
- 四个角的圆弧比直边醒目，视线先落在角上；
- 圆角外侧还有方形窗口底色，把直边在视觉上"切断"了。

补上 DWM 圆角后方形底色消失，四条边随之连贯。

## 侧栏 / 大纲栏展开收起状态不记忆

以前三个开关只改内存，从不写盘（原代码注释写的就是"会话内切换不写盘"），所以关掉窗口再打开就忘了。

现在切换即写回配置：

- 侧栏：写 `sidebarDefaultView`（`close` / `files` / `outline`）
- 大纲栏：写 `outlineVisible`（`true` / `false`）

下次启动按上次状态恢复。写盘失败会弹提示，但不会把界面改回去（保持用户刚做的操作）。

## 拖窄侧边栏提示"配置内容无效，请检查当前修改。"

界面允许把文件栏拖到 160px，配置校验却要求 `sidebarWidth ≥ 220`。拖到 160–219 这段松手时，界面合法、写盘被拒，于是弹这句提示。

现在配置校验下限改为 160，与界面 `FILE_MANAGER_PANEL_MIN_WIDTH` 对齐。（大纲栏两端本来就都是 160，不受影响。）

- 实现：`mdreader-electron/src/data/config/configSchema.js` 的 `sidebarWidth.minimum` 220 → 160，同步 `configLoadSanitizer.test.js` 断言。

## 大纲栏底部出现横向滚动条

空大纲时显示的占位插画（ant-design-vue 的 `Empty`）固定 184px 宽，比最窄 160px 的大纲栏还宽，在居中 flex 里溢出，把 `scrollWidth` 撑到 172 → 出现横向滚动条。

现在给占位块加 `max-width: 100%` / 图片 `height: auto`，并把滚动容器设为只在纵向滚动。

- 实现：`mdreader-web/src/components/editor/MarkdownMenu.vue`

## 窗口大小 / 位置不记忆（"举一反三"）

同一个毛病：窗口几何从来没有存过，每次启动都是「主屏工作区 3/4」的默认尺寸、系统摆到哪算哪。

现在记在 `data/window-state.json`（**没有**塞进 `config.json`：窗口几何是会话状态，和 `tab-group.json` 同类，配置备份不该带屏幕坐标；`config.json` 又是完整对象校验，加字段容易再踩「写盘被拒」的坑）。

- 记常规窗口矩形 + 是否最大化；最大化时只记"还原后"的矩形，还原再最大化，取消最大化还能回到原来的大小；
- 拖动/缩放/最大化防抖 400ms 异步写，关窗时同步写（最后一个窗口关掉进程就退出，异步写会被截断）；
- 恢复前做可见性校验：和任一显示器工作区重叠不足 100×60（例如上次用的副屏拔掉了）就不恢复，按默认居中；尺寸比当前屏幕大时先收缩再拉回可视区；
- 只让本进程的第一扇窗口套用记忆，之后新建窗口继续系统层叠摆放。

- 实现：新增 `mdreader-electron/src/data/windowState.js`；`windowLifecycleService.js` 建窗时恢复、挂 `attachWindowStatePersistence`；`main.js` 在 `initTabGroup()` 之后 `initWindowState()`。

## 拖入文件不会替换空白标签

**现象**：打开软件是空白标签，从资源管理器拖一个 md 进来，会**另开一个标签**，空白标签留在那儿。

**原因**：拖放打开走的是"固定新开标签"这条交互（`openMode: 'new-tab'`），而用户想要的"空白标签被占用"逻辑只写在"拖进编辑区"那条路上，窗口其它位置、标签栏上的拖放都没走它。

**修复**：窗口任意位置、标签栏、编辑区三条拖放路径统一判断目标栏是不是空白标签——是就复用它、把文件开进这个栏并关掉空标签；**正在编辑（有未保存改动）的标签不算空白**，照旧新开标签，绝不吞掉用户正在写的内容。

顺带修了一个连带缺陷：打开动作会切换会话，行内请求随即被判为 `request-invalidated`，旧代码把它当失败、于是空标签没关。现在把这种"其实已经打开了"的结果按成功处理，并且**确认目标路径的标签真的出现了**才关空标签（避免误关）。

- 实现：新增 `mdreader-web/src/util/document-session/documentDropOpenInPaneUtil.js`；`fileDragDropUtil.js` 的 `openDroppedFileReplacingBlank` 加 `request-invalidated` 容错与 `hasOpenTabForPath` 校验；`HomeView.vue` / `DocumentTabBar.vue` / `MarkdownEdit.vue` 接上。

## 没改过的文件关闭时也弹"未保存"提示

**现象**：用 CRLF 换行（Windows 记事本、很多编辑器默认就是 CRLF）的 md 文件，哪怕只读、一个字没动，关标签也会弹"存在未保存的修改"。

**原因**：编辑器内部统一用 LF，挂载时把正文里的 `\r\n` 规整成 `\n` 回传给主进程；主进程拿磁盘原文（CRLF）跟它逐字符比较，一个字符对不上就判定为"脏"。而写盘是原样写回，所以这个差异永远不会自己消失。

**修复**：打开时记下文件原来的换行风格（`diskSnapshot.lineEnding`），渲染层回传的正文先按同一风格展开再比较与落盘。效果：CRLF 文件不再假脏，保存时也仍然写回 CRLF，**不改变用户文件的换行风格**。

- 实现：新增 `mdreader-electron/src/util/document-session/lineEndingUtil.js`；`documentCommandService.js` 收 `document.edit` 时先做换行归一；`documentSessionFactory.js` / `watchCoordinator.js` / `saveCoordinator.js` 各自更新 `lineEnding`。

## 拖动窗口后部分青色边框消失

**现象**：刚打开时四边都有青色边框，拖动一下窗口，某几条边就没了。

**原因**：窗口没有 `WS_THICKFRAME`，Windows 11 的 DWM 依然会在窗口最外圈画**它自己的 1px 边框**（颜色随激活/失焦状态变）。这层边框画在页面之上，正好压住渲染层那圈 1.33px 的青色线；拖动/切换激活状态时 DWM 重画这层，于是"有的边被盖住"。

**修复**：设 `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` 让 DWM 不画自己的边框，只留渲染层那圈青色；并在移动/缩放/最大化/还原/焦点切换后**重新下发**这两个 DWM 属性（120ms 节流），防止系统在某些状态下把它们还原。

- 实现：`windowStyleUtil.js` 新增 `applyNativeFrameAppearance`（圆角 + 隐藏系统边框）与 `createUint32AttributeBuffer`；`windowLifecycleService.js` 改调它并新增 `attachNativeFrameRefresh`。

## 升级说明

Windows 直接覆盖安装，用户数据在 `%APPDATA%\mdreader`，不受影响。本版放宽了一个数值下限、多记两个开关状态和一份窗口几何，没有改动配置结构（窗口记忆是独立的 `window-state.json`，首次运行自动生成）。
